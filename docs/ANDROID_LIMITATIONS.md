# Ограничения Android TV и обходные пути

Ниже пометка «✔ проверено» означает, что поведение подтверждено на Xiaomi Mi TV Stick (Android 11 / API 30, Amlogic).

## Захват экрана

| Ограничение | Что делает TVconnect |
|---|---|
| MediaProjection требует нажать «Начать» на ТВ **в каждом сеансе** (Android 10+; на 14+ токен нельзя переиспользовать). ✔ проверено | При `start_video` открывается системный диалог, а клиент показывает «Подтвердите захват на телевизоре». Без человека у ТВ видео можно получить только в **ADB Mode**. |
| Если клиент отключился, пока диалог открыт, диалог оставался висеть. ✔ найдено и исправлено | При закрытии сессии диалог закрывается через `finishActivity`. |
| На Android 14+ нужен foreground service типа `mediaProjection`, причём его нужно запустить **до** `getMediaProjection`. Одна проекция может создать только один VirtualDisplay. | Служба работает как `specialUse` и переключается в `mediaProjection` после согласия. VirtualDisplay переиспользуется при смене качества (`resize` + `setSurface`). |
| На некоторых прошивках нет диалога MediaProjection. | Клиент сообщает об ошибке. Обходной путь — ADB Mode (`screenrecord`). |
| DRM и `FLAG_SECURE` (Netflix и т. п.) захватываются чёрным экраном. | Обойти нельзя и не обходим. |
| **Аппаратный H.264-энкодер может быть недоступен приложениям.** На Mi TV Stick `OMX.amlogic.video.encoder.avc` объявлен в `/vendor/etc/media_codecs.xml`, но `MediaCodecList` его не показывает, а `createByCodecName` возвращает `0xfffffffe`. ✔ проверено | Перебираются энкодеры: сначала аппаратные, затем «скрытые» вендорские по имени, затем программный `c2.android.avc.encoder`. Программный энкодер на этом устройстве тянет 1080p, но сильнее грузит CPU, поэтому рекомендуем 720p. |
| Энкодер присылает кадры только при изменении экрана. | Задан `KEY_REPEAT_PREVIOUS_FRAME_AFTER = 100 мс`, ключевой кадр отправляется по запросу клиента. |

## Ввод

| Ограничение | Что делает TVconnect |
|---|---|
| Обычное приложение не может вставлять KeyEvent: `INJECT_EVENTS` доступно только системным приложениям. | Ключевые события отправляет ADB Mode (`input keyevent`), любые `KEYCODE_*`. |
| `GLOBAL_ACTION_DPAD_*` есть только на Android 13+. | На Android < 13 D-pad эмулируется переносом фокуса Accessibility (`focusSearch` + `ACTION_FOCUS`), а OK — через `ACTION_CLICK`. ✔ проверено: фокус перемещается. |
| **Жесты `dispatchGesture` на части прошивок отменяются системой.** ✔ проверено: Mi TV Stick отменяет каждый жест. | ТВ сообщает клиенту `gesture_cancelled`. Клиент повторяет действие через ADB и до конца сеанса отправляет мышь через ADB. ✔ проверено: тап открывает нужный экран. |
| MENU, Tab, Escape, F-клавиши через Accessibility отправить нельзя. | В режиме `auto` они идут через ADB; без ADB клиент показывает подсказку. |
| Ввод текста: `adb shell input text` понимает только ASCII. | Не-ASCII текст (кириллица) вставляется через Accessibility `ACTION_SET_TEXT` в поле, на котором стоит фокус. |
| ADB `input` медленный: каждая команда запускает `app_process`, около 100–300 мс. | Используется одна постоянная `adb shell`-сессия, подряд идущие клавиши склеиваются в одну команду `input keyevent a b c`. |
| Курсора для touch-ввода на ТВ нет. | Курсор рисуется оверлеем `TYPE_ACCESSIBILITY_OVERLAY`; для этого не нужно `SYSTEM_ALERT_WINDOW`. |
| В «touch mode» на Android первый тап по элементу с `focusableInTouchMode` только ставит фокус. ✔ найдено | У кнопок TV-приложения флаг снят, нажатие срабатывает с первого тапа. |
| Пункт «Спец. возможности» спрятан на части Google TV. | Включение через `adb shell settings put secure enabled_accessibility_services ...` (см. BUILD.md). |

## Буфер обмена

| Ограничение | Что делает TVconnect |
|---|---|
| Запись в буфер разрешена и фоновому приложению. | При вставке и автосинхронизации текст с ПК кладётся в буфер ТВ (`setPrimaryClip`). |
| Вставка в чужое поле. | Через Accessibility `ACTION_SET_TEXT` текст вставляется в позицию курсора с заменой выделения. Если поле не принимает вставку, используется `ACTION_PASTE`. ✔ проверено: кириллица, эмодзи, многострочный текст. |
| **Читать буфер Android 10+ разрешает только приложению на переднем плане или IME.** | Ctrl+C возвращает выделенный текст поля в фокусе (или весь текст поля / элемента). Чтение системного буфера — запасной вариант, он работает, только если TVconnect открыт на экране. ✔ проверено |
| В ADB Mode нет TV-приложения, а `input text` понимает только ASCII. | Вставка печатается через `input text` по частям, переводы строк отправляются как ENTER. Для кириллицы нужен Native Mode. Копирование с ТВ в ADB Mode не поддерживается. |

## Фон, автозапуск, сеть

| Ограничение | Что делает TVconnect |
|---|---|
| Запуск Activity из фона запрещён (Android 10+). Это касается диалогов сопряжения и захвата. | Исключение действует, если у приложения включена служба Accessibility или выдано `SYSTEM_ALERT_WINDOW` (`appops`). Также работает, когда TVconnect открыт на экране. |
| На Android 15 из `BOOT_COMPLETED` нельзя запускать foreground service типа `mediaProjection`. | Слушатель стартует как `specialUse`, захват включается позже, после согласия. |
| OEM-лаунчеры могут убивать фоновые службы; часть ТВ не шлёт `BOOT_COMPLETED` при выходе из standby. | Служба помечена `START_STICKY`. Если служба не поднялась сама, откройте TVconnect вручную. |
| Роутер может блокировать multicast (mDNS). | Есть UDP-broadcast fallback (порт 47801), ручной ввод IP и список устройств из `adb devices`. На ТВ взят `MulticastLock`. |
| `screenrecord` работает не дольше 3 минут за запуск. | Поток автоматически перезапускается (разрыв около 0.3 с). |
| Парсер H.264 выдаёт кадр только когда приходит следующий, а при статичном экране `screenrecord` ничего не шлёт. ✔ найдено | Если поток молчит 30 мс, парсер сбрасывается. |

## Следующий шаг (Phase 3): собственный shell-агент

Самый практичный путь к низкой задержке и полному управлению без MediaProjection — поступить как open-source утилиты
зеркалирования: запустить наш dex через `adb shell app_process` с правами `shell`. Тогда доступны:

- `InputManager.injectInputEvent` (через рефлексию): любые клавиши и мышь с задержкой меньше 10 мс;
- `SurfaceControl` / `DisplayManager` для захвата без диалога и без лимита в 3 минуты;
- аппаратный энкодер, если вендор открывает его процессам `shell`.

Root для этого не нужен, хватает включённой отладки по сети.
